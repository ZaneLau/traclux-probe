# 方法与边界

本社区实现使用 CSSM-HI 的抽象目标：D1–D6 是状态坐标，选点以全局覆盖优先。正式理论、实验和数据还在审查中；此公开候选不宣称复制完整 V4.2 引擎。本文件只说明本仓可验证的机制。

1. 用户逐条为问题标注 D1–D6，每维恰有一个合法状态；不兼容组合报错。交互向导的少量字符串建议没有准确率验证，每维必须明确确认。本工具不自动推断用户的真实意图，标签质量由输入者负责。
2. 每题产生 15 个维度对；给定预算，以新增覆盖的状态对数量贪心选取，平局保留输入顺序。这是**组合覆盖近似**，非统计估计，也不是生产 Node1 全功能移植。
3. 对照基线是原始文件顺序的前 N 题，容易受到输入排序影响。它演示检查方法，不能作为论文效果证据。严谨试验须加入随机/主题配额/关键词扩写和同预算多次盲测，并衡量经人工确认的重要盲点。
4. 仅导入已有回答。每条回答记录问题 ID、入口、来源、时间、答案和引文 URL；录入声明本身未核验，不验证 URL 内容、采样授权或客户端真实性。缺答案保留 `null`，不能拿覆盖数代替回答曝光。
5. API、浏览器客户端、地区、账户、工具及历史会造成差异；本仓没有跨入口校准。报告不能称“普通用户真实曝光率”。

样例的商标、问题与响应纯属虚构。真实客户输入、账号密钥、第三方面板或爬虫会引入额外授权、隐私与成本问题，应在独立产品路径验证。
